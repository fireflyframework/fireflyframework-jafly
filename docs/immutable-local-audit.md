# Local transactional immutable audit and permanent export intent

This opt-in capability appends canonical kernel audit values and a permanent outbox intent inside the owning command's existing local R2DBC transaction. It creates no Spring bean, transaction, connection pool, default schema, security grant or background subscriber. The best-effort security audit logging SPI remains unchanged.

## Construct on the owning resource graph

The owner constructs one stable `OwnedLeaseConnectionFactory`, `DatabaseClient`, `R2dbcEntityTemplate` and `R2dbcTransactionManager`, verifies them with `BoundedR2dbcResources.verify`, and uses the existing `DefaultBoundedRootTransaction`. Pass those exact objects to `SpringDataTransactionalAuditAppender`, together with a mandatory genuine `AuditAppendAuthority` and the **same Clock and LongSupplier instances used for the original operation budget**. Do not wrap or replace a caller's client/template, converters or statement filters.

The appender's `append(scope, event)` must be composed into the owning root work publisher, before that publisher completes. It proves the private active invocation and exact RootTransactionScope/resource graph before admission, then uses the transaction-bound same connection. It never invokes a second root or generic joining TransactionalOperator. Ordinary ambient transactions, stale/foreign scopes and mismatched graphs refuse. Narrowing the genuine original scope preserves its identity.

The authority port must resolve the authenticated current actor, authorize the resource and action, and verify the event's outcome, process, evidence digest and policy facts. Kernel values are claims, not authentication. The appender compares the complete actor and stream against the permit at admission and again before native completion. There is no default or successful unavailable provider. The actor's platform tenant key is an exact String namespace; the resource tenant remains a separate UUID. Do not invent a UUID mapping or equate those tenants.

## Persistence and replay

Every public `LocalAuditRepository` operation also requires the genuine RootTransactionScope and the same verified factory/client/template/manager graph; it cannot fall back to an ordinary ambient transaction. It exposes no inherited general CRUD API. Its mapped statement helpers are private.

`SpringDataLocalAuditRepository` uses the owning template's genuine mapping strategy/converter and StatementMapper for ordinary inserts and head CAS. Every insert/update must observe exactly one actual affected row. Zero, multiple and missing observations refuse. It stores every canonical kernel field, including separate Instant seconds/nanos, with no serializer-dependent JSON. Event uniqueness is `(resource_tenant_id,event_id)` across all streams in that tenant. The stream head CAS includes the whole scope, expected sequence and previous hash.

The immutable event and its immutable `AUDIT_EXPORT` intent are inserted in the same local transaction as the head and business work. The next append links the prior hash. Exact replay reads the original full event, verifies its canonical record hash and full permanent outbox, and returns the original record without changing its timestamp or sequence. Different content under the same event ID refuses. A duplicate database error propagates without reading or continuing in the aborted transaction. A mandatory append failure marks the genuine owner transaction rollback-only, so catching a logical append refusal cannot commit the business effect. Marking performs no SQL and never clears rollback-only.

The API returns `ProvisionalAppend`, which is not a durability receipt. The owner must independently inspect its original RootCompletion: acknowledged commit, completed boundary and complete cleanup are separate required facts. A caught refusal can yield a completed rollback boundary with **no commit**; returning a work value does not change that fact. RootTransactionException can also retain acknowledged-commit facts despite withholding a value or incomplete cleanup. Do not infer no-effect or replay a business effect from an exception alone.

The library cannot detect an owner that omits the mandatory audit call. Explicit owner integration and native business/audit effect capture remain adoption gates. External export/delivery, mutable retry leases and ACK state must be separate from permanent event/outbox rows; no delivery worker is supplied here.

## Explicit PostgreSQL contract

`modules/r2dbc/src/main/resources/db/optional/immutable-audit/postgresql.sql` is a standalone explicit transaction, outside default Flyway locations and versioned naming. It must be deliberately installed once by a separately delegated installer. It neither baselines/repairs history nor assumes any owning business table. There is no automatic Flyway bean. Provision exact NOINHERIT/NOSUPERUSER/NOBYPASSRLS/NOCREATEDB/NOCREATEROLE/NOREPLICATION roles beforehand: non-login `firefly_audit_guard`; login `firefly_audit_writer` and `firefly_audit_reader`. The installer must be able to SET the guard and hold public CREATE WITH GRANT OPTION. The script removes its temporary guard public CREATE grant before commit.

The owning business pool uses `firefly_audit_writer`; the deployment must deliberately grant that role its own core's required business privileges. The script grants no business-table permission. The writer cannot own audit tables or use the private schema. Ordinary reader grants cannot mutate originals; reader RLS is denied by default until a separately admitted export/read adapter is implemented. No general read API is supplied.

The concrete native repository calls fixed technical functions on the same transaction. Enter binds actual session/xid/backend, nonce, event, whole resource scope and full admitted actor, serializes scoped event/stream mechanics, and returns the real database recording clock and a cap at most five seconds. The appender narrows its original paired budget with a one-millisecond completion margin; no new deadline is granted. Native completion and a deferred constraint require the immutable event, complete permanent intent, current head and native-time linkage. Multiple sequential append contexts can exist within one owner transaction, each completed separately and still checked at the original boundary. The fixed native clock/functions do not authenticate their actor parameters or establish a genuine owner permit.

Database primary/foreign keys enforce tenant-scoped identity, unique stream sequence, immutable predecessor links and current head linkage. UPDATE/DELETE triggers and grants protect originals for ordinary runtime roles. The adapter computes/rechecks canonical kernel hashes; this SQL contract does not independently reimplement the canonical hash protocol. Privileged storage administrators remain outside ordinary-role protection. Actual PostgreSQL mapping, constraints, privileges, rollback and restart behavior require the separately approved native fixture; source tests are not that evidence.

## Remaining operational and compliance work

No checkpoint custody, authenticated signing, WORM storage, retention/hold/disposition engine, trusted reference-clock operations, external export acknowledgment or restore evidence is supplied. There is no invented global DORA retention period and no compliance certification. Full framework CQRS/saga/TCC/batch lifecycle integration and explicit per-core/process adoption remain separate gates. Existing owner journals must retain their current contracts until a real integration is qualified.
